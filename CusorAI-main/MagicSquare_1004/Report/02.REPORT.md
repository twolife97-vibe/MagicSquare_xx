## 3. 인터뷰 진행 기록 (시뮬레이션)

> **Role 1** = 인터뷰어 (Mom Test 규칙, 질문만) · **Role 2** = 페르소나 (plausible한 과거 사실만)

### Turn 1

**Role 1 — 인터뷰어**

> 지난주 부분 마방진 과제할 때, 빈칸 두 개를 채운 **직후**에 뭘 했어? 그 순간부터 제출하기 전까지 순서대로 말해줘.

**Role 2 — 페르소나 (가상)**

> 빈칸에 7이랑 8 넣었어. 노트북에서 `print`로 격자 찍고, 행 네 개 합이 34인지 손으로 더해봤어.  
> 세 번째 행이 33이 나와서 8을 9로 바꿨어. 다시 행·열·대각선 전부 더했는데, 이번엔 대각선 하나가 35.  
> 격자만 보면서 "어디가 틀렸지?" 하고 10분 넘게 같은 숫자만 다시 세었어.  
> 결국 친구한테 "대각선 어떻게 확인해?" 물어봤고, 친구가 "`(0,0)+(1,1)+(2,2)+(3,3)` 이렇게 더해"라고 알려줬어.  
> 그다음에야 대각선 두 개까지 맞는 걸 확인하고 제출했어.

| Mom Test 평가 | 결과 |
|---------------|------|
| 사실 | ✅ (가상이지만 plausible) |
| 과거 | ✅ ("지난주") |
| 구체 | ✅ (7·8→9, 3행 33, 대각선 35, 10분+) |
| 솔루션 혼입 | ✅ 없음 |

### Turn 2 (추궁)

**Role 1 — 인터뷰어**

> "10분 넘게 같은 숫자만 다시 세었다"고 했는데, 그때 **몇 번** 정도 행·열·대각선 합을 다시 계산했어?  
> 그리고 **어느 줄**이 틀렸는지 바로 알 수 있었어, 아니면 "34가 아니다"만 알고 **어느 줄인지**는 몰랐어?

**Role 2 — 페르소나 (가상)**

> 행·열·대각선 **10줄** 전부 다시 세는 걸 **최소 4~5번** 반복한 것 같아.  
> "34가 아니다"는 바로 알았는데, **어느 줄**인지는 몰랐어.  
> 세 번째 행만 33인 줄은 처음에 알았는데, 8→9로 바꾼 뒤엔 **행은 다 34**인데 **대각선 하나**만 틀린 거였어.  
> 격자만 보면서 "이 칸 바꿨더니 저 대각선이 깨졌나?" 하고 **줄 단위로 짚지 못하고** 칸 하나씩 의심했어.  
> 엑셀에 격자 복사해서 `SUM` 넣어볼까도 했는데, 과제가 "노트북만"이라서 안 했어.

| Mom Test 평가 | 결과 |
|---------------|------|
| 사실 | ✅ |
| 과거 | ✅ |
| 구체 | ✅ (10줄, 4~5회, 줄 vs 합 구분) |
| 솔루션 혼입 | ✅ 없음 |

### Turn 3 (추궁)

**Role 1 — 인터뷰어**

> 친구한테 물어보기 **직전**, 혼자서 시도한 방법 중 **가장 오래 걸린 것** 하나만 골라줘.  
> 그걸 **몇 분** 정도 했고, **끝에 뭐가 막혔는지** 구체적으로.

**Role 2 — 페르소나 (가상)**

> **대각선 두 개**를 확인하는 방법이 제일 오래 걸렸어. 행·열은 "가로·세로 더하기"가 뻔한데, 대각선은 **어느 칸 네 개**인지 매번 헷갈렸어.  
> `(0,0)(1,1)(2,2)(3,3)`만 계산하고 `\` 방향은 빼먹었거나, `(3,0)(2,1)(1,2)(0,3)` 칸을 잘못 집어서 **5~7분** 썼어.  
> 끝에 막힌 건 "**10줄 중 어느 줄이 34가 아닌지** 한 번에 보는 방법"이 없었다는 거야.  
> `print` 결과만 보면 "뭔가 틀렸다"는 느낌만 있고, **실패한 줄 목록**은 없었어.  
> 친구한테 물어본 건 "대각선 공식"이었지, "8이 맞냐 9가 맞냐"를 대신 풀어달라고 한 건 아니었어.

|---------------|------|
| 사실 | ✅ |
| 과거 | ✅ |
| 구체 | ✅ (5~7분, 칸 좌표, 실패 줄 목록 부재) |
| 솔루션 혼입 | ✅ 없음 |

## 4. Mom Test 분석

### 4.1 표면 문제 (잘못된 정의 — 솔루션·지식 혼입)

| 표면 문제 | 왜 표면인가 |
|-----------|-------------|
| "대각선 공식을 몰라서 친구한테 물어봤다" | **지식·튜토리얼** 이슈 — 한 번 알면 끝 |
| "엑셀 쓰고 싶었는데 노트북만이라 못 썼다" | **도구·과제 규칙** 제약 |
| "칸 하나씩 의심했다" | **풀이 전략** — Solver/힌트 제품으로 오해 가능 |

Mom Test에서 **문제 정의에 쓰면 안 되는** 문장 (참고):

- BCE / `MagicSquare` / `Solver` / `GridUI` **프로그램부터 만든다**
- 빈칸 **자동 채우기** / **힌트** / Solver 알고리즘
- PyQt **UI** 먼저 설계
- BCE 설계만 하고 **테스트 없이** 끝

### 4.2 진짜 문제 (한 문장)

> 4×4 부분 마방진에서 빈칸을 채운 직후, **행·열·대각선(10선) 합 34 여부를 빠르게 확정하지 못하고**, 틀렸을 때 **어느 줄**인지 바로 짚지 못해 **같은 검산을 4~5회·10분 이상** 반복한다.

※ 시뮬레이션 분석 초안의 "어느 칸"은 증거가 약함 — **줄 단위 식별**이 핵심.
