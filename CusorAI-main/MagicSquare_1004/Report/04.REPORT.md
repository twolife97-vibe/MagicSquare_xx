## 1. 한 장 요약 — 복잡한 8계층을 4그룹으로

교육 자료의 8계층+Hook은 **역할이 겹쳐 보여** 복잡합니다. 실무에서는 아래 **4그룹**만 기억하면 됩니다.

```
┌─────────────────────────────────────────────────────────┐
│  Cursor에서 MagicSquare_1004 작업할 때                   │
├─────────────────────────────────────────────────────────┤
│  ① 준비물    Harness(폴더·pytest) + Rule(.cursorrules) │
│  ② 작업 방식 Ask(리뷰) vs Agent(만들기) + Command(/)  │
│  ③ 검증      pytest + 성공 기준 체크                    │
│  ④ 나중에    Skill · Hook · MCP (세션 3 필수 아님)      │
└─────────────────────────────────────────────────────────┘
```

| 교육 자료 8계층 | 실무 4그룹 | Cursor에서 어디? |
|----------------|-----------|------------------|
| Model | *(설정만)* | Settings → Models / 채팅 모델 드롭다운 |
| Agent | **② 작업 방식** | 채팅 Ask / Agent / Plan |
| Harness | **① 준비물** | `src/`, `tests/`, `pyproject.toml`, 터미널 |
| Rule | **① 준비물** | 루트 `.cursorrules` |
| Command | **② 작업 방식** | `.cursor/commands/*.md` → 채팅 `/이름` |
| Skill | **④ 나중에** | `.cursor/skills/*/SKILL.md` |
| Tool/MCP | **④ 나중에** | Settings → MCP, Shell(pytest) |
| Test Loop | **③ 검증** | `pytest`, `/review-*` Command |
| Hook | **④ 나중에** | `.cursor/hooks.json` + Settings → Hooks |

> **핵심:** 세션 3에서 **꼭 만들 것**은 `.cursorrules` + Command 1개 + pytest Harness입니다. Skill·Hook·MCP는 나중에 추가해도 됩니다.

## 2. MagicSquare_1004 주제 (이미 확정)

> **4×4 부분 마방진에서 빈칸을 채운 직후, 행·열·대각선 10선이 각각 34인지 빠르게 확정하고, 틀리면 어느 줄인지 바로 짚을 수 있게 검증 규칙과 테스트 루프를 만든다.**

| R-G-I-O | 내용 |
|---------|------|
| **R** | 4×4 부분 마방진 학습자 — 빈칸 채운 뒤 **맞았는지 확인** |
| **G** | 10선 합 34 **즉시 판정** + 실패 시 **어느 줄**인지 표시 |
| **I** | 4×4 격자 (`0`=빈칸, `1~16`=채운 칸) |
| **O** | `pass` / `fail` / `incomplete` + 실패 줄 ID 목록 |

**성공 기준 3개**

| # | 기준 | 검증 방법 |
|---|------|-----------|
| 1 | 10선 합 34를 **한 Command**로 검사 | `validate_lines(grid)` 호출 |
| 2 | Red→Green 테스트 동작 | `pytest tests/ -v` |
| 3 | 실패 시 **어느 줄**인지 Output에 명시 | Red 테스트 assert |

## 3. Ask vs Agent — 가장 자주 하는 실수

| 모드 | 하는 일 | 언제 쓰나 | MagicSquare 예 |
|------|---------|-----------|----------------|
| **Ask** | 답변·리뷰만. **파일 수정 없음** | 규칙 검토, R-G-I-O, BCE 리뷰 | "`.cursorrules` 빠진 규칙 찾아줘, 수정하지 마" |
| **Agent** | 파일 생성·수정, 터미널 실행 | 테스트·코드 작성, pytest | "`tdd-red` 따라 실패 테스트 작성해줘" |

**기억할 한 줄:** "리뷰만" → **Ask**. "만들어줘" → **Agent**.

## 4. 5단계 실습 — 순서대로만 하면 됨

```
[1] R-G-I-O 확인 (Ask, 5분)     ← 이미 Report/03에 있음
      ↓
[2] Harness 골격 (Agent)        ← src/, tests/, pyproject.toml
      ↓
[3] Rule 작성 (Agent)           ← .cursorrules
      ↓
[4] Command 1개 (Agent)         ← /tdd-red
      ↓
[5] Test Loop 확인 (Agent)      ← pytest FAIL → PASS
```

### Step 1 — R-G-I-O 확인 (Ask, 수정 없음)

이미 [Report/03.REPORT.md](./03.REPORT.md)에 작성됨. 아래만 확인:

```
@Report/03.REPORT.md
세션 3 R-G-I-O와 성공 기준 3개가 MagicSquare 도메인에 맞는지 리뷰만 해. 파일 수정 금지.
```

### Step 2 — Harness 골격 (Agent)

```
MagicSquare_1004 세션 3용 최소 Harness만 만들어줘.
- pyproject.toml (pytest만)
- src/validate_lines.py (빈 파일 또는 함수 시그니처만)
- tests/test_validate_lines.py (빈 파일)
코드 본문·테스트 본문은 아직 작성하지 마. 골격만.
```

### Step 3 — Rule 작성 (Agent)

```
루트에 .cursorrules 초안을 만들어줘.
도메인: 4×4, 빈칸 0, 1~16, 마법상수 34, 10선 검증
API: validate_lines(grid) → ok, status, lines[]
TDD: RED→GREEN, assert 완화·skip 금지
AI: 한국어, git commit은 사용자 요청 시만
40~60줄. 다른 파일은 만들지 마.
```

### Step 4 — Rule 보완 (Ask, 수정 없음)

```
@.cursorrules
Rule 관점에서 빠진 규칙을 표로 알려줘. 파일 수정 금지.
체크: 10선 정의, 마법상수 34 SSOT, incomplete 처리, TDD 금지사항
```

### Step 5 — Command + Test (Agent)

```
.cursor/commands/tdd-red.md 를 만들어줘.
MagicSquare validate_lines RED 단계만.
포함: Phase 선언, AAA 테스트 절차, pytest 예시, 금지(src/ 수정)
```

그다음 Agent 모드:

```
/tdd-red
T2: 한 행 합 ≠ 34인 Red 테스트 작성해. src/ 수정 금지.
```

pytest 확인:

```
pytest tests/test_validate_lines.py -v
```

**RED 성공 = 테스트가 FAIL** (아직 구현 없으므로)

## 6. Command 사용법 (30초)

1. 채팅 입력창에 `/` 입력
2. `tdd-red` 선택
3. 뒤에 작업 내용 추가:

```
/tdd-red
T4: 대각선만 ≠ 34인 Red 테스트. tests/만 수정.
```

| Command | 하는 일 | 모드 |
|---------|---------|------|
| `/tdd-red` | 실패 테스트만 작성 | Agent |
| `/tdd-green` | 최소 구현으로 테스트 통과 | Agent |
| `/pytest-validate` | validate_lines 테스트 실행 | Agent |
| `/review-rules` | 규칙·계약 리뷰만 | Ask |

## 7. Test Loop — "됐는지" 확인하는 법

| 단계 | 명령 | 기대 결과 |
|------|------|-----------|
| RED | `pytest tests/ -v` | **FAIL** (미구현) |
| GREEN | `pytest tests/ -v` | **PASS** |
| 회귀 | `pytest tests/ -v` | 전부 PASS 유지 |

**Agent에게 시키기:**

```
pytest tests/ -v 실행하고 PASS/FAIL 표로 요약해줘.
```
