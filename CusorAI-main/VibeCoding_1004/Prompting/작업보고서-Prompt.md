현재 `add` 함수가 **보장하는 것**과 **보장하지 않는 것**을 나눠서 정리하면 아래와 같습니다.

## 보장되는 것

### 1. 타입 (컴파일 시점)
TypeScript 기준으로 `add`는 다음 시그니처를 가집니다.

```typescript
(a: number, b: number) => number
```

- 인자는 **숫자 2개**여야 합니다.
- 반환값은 **숫자**입니다.

### 2. 동작 (런타임)
`a`와 `b`가 **일반적인 유한 숫자**(`number`)일 때:

- JavaScript `+` 연산과 **동일한 결과**를 반환합니다.
- 정수, 실수, 양수, 음수, 0 조합 모두 **같은 규칙**으로 더합니다.

예:

```typescript
add(2, 3);      // 5
add(-2, 3);     // 1
add(1.5, 2.3);  // 3.8
```

### 3. 부수 효과 없음
- 입력을 바꾸지 않습니다.
- 전역 상태를 바꾸지 않습니다.
- I/O, 네트워크, 예외 throw도 없습니다.

---

## 보장되지 않는 것

### 1. 수학적 정확도 (부동소수점)
IEEE 754 부동소수점 한계 때문에 **모든 실수 덧셈이 수학적으로 정확하다고 보장되지 않습니다.**

```typescript
add(0.1, 0.2); // 0.30000000000000004 (0.3이 아님)
```

금융·과학 계산처럼 정밀도가 중요한 경우에는 **별도 처리가 필요**합니다.

### 2. 입력 검증
다음은 **막지 않습니다.**

| 입력 | 결과 |
|------|------|
| `NaN` | `NaN` |
| `Infinity` | `Infinity` 등 JS 규칙대로 |
| `Number.MAX_VALUE` 초과 등 | `Infinity` 가능 |

“유효한 숫자만 받는다”는 런타임 검증은 없습니다.

### 3. TypeScript 타입만으로는 막을 수 없는 것
런타임에 문자열 등이 들어오면 TypeScript가 막아주지 않습니다.

```typescript
add("1" as any, 2); // "12" (문자열 연결)
```

타입을 지키면 이런 일은 없지만, **런타임 타입 검사는 없습니다.**

### 4. JSDoc 예시와의 1:1 일치
JSDoc의 `// 3.8`, `// -0.7` 같은 주석은 **설명용**이며, 부동소수점 환경에 따라 표현이 달라질 수 있습니다.
